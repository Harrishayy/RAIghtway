# Frontend UI Specification

This file covers what the UI must contain and how a user moves through it. It deliberately doesn't prescribe visual layout; that comes later.

---

## Design principles
- **Professional, not AI-generated looking.** It should feel like a real operations product, not a template or a typical AI demo.
- **A clean dashboard.** No unnecessary buttons or controls; every element on screen has a clear purpose.
- **Easy to understand.** Someone seeing it for the first time should follow what's happening without explanation.
- **The map is one part of the dashboard, not the whole screen.** Users can toggle it on and off.
- **Avoid the "map on the left, panel on the right" layout.**

---

## User flow

### 1. Add today's footage
- A clear area where the user drops in the day's footage.
- After dropping, each video appears with its own **progress bar** showing analysis status.

### 2. Browse the analysed videos
- Once analysed, every video appears in a **directory**.
- Each video has its own page or entry with:
  - **An explanation** of what was found in it, generated during analysis.
  - **Metadata** gathered during analysis, e.g. where and when it was recorded, the issues found, their type and severity, and their locations.

### 3. Map view
- A map showing **where each defect is in the city**, using the GPS data from the footage.
- The map can be **toggled on and off**, so it doesn't permanently take up the dashboard.
- **Clicking a highlighted issue on the map** shows a **frame from the footage with a bounding box** around the issue. This makes each issue immediate and easy to understand, and is a key feature.

### 4. Report
- A report **summarising the overall situation** across all analysed footage.
- The report includes **dispatch recommendations**: which teams need to be sent to fix the issues. These are generated by an LLM and appear directly in the report.

### 5. Route optimisation
- Once the dispatch teams are decided, **cuOpt optimises the route for each individual crew**.
- Each crew's route is **shown on the map**.

---

## Summary of required UI elements
| Element | Purpose |
|---|---|
| Footage drop area | Add the day's footage |
| Per-video progress bars | Show analysis progress |
| Video directory | Browse every analysed video |
| Video detail (explanation + metadata) | Show what analysis found in each video |
| Toggleable map | Show where every issue is |
| Clickable issue markers → frame with bounding box | Show exactly what each issue looks like |
| Report | Summarise the situation and recommend dispatch teams |
| Crew routes on the map | Show the optimised route for each crew |

---

## Open points
- **Bounding boxes:** the provided models don't produce boxes for road defects out of the box, so how we generate them still needs testing.
- **Analysis time:** analysing a full day's footage takes a while, so how we show it live is still to be decided.
