    Part two

    Build spec

    How the console is built: a pnpm monorepo with a Next.js app, laid out so each workstream owns a folder and builds against fixtures. It follows the Casework layout: routes → features → domain → ui → tokens, with contracts in one package.

    Stack and libraries

    TypeScript across the web app and the contracts; the models and the pipeline stay in the Python backend from the architecture. Pin exact versions in the lockfile.

    Architecture

    Five layers; imports only point down. Every screen and Dash read the same polled resources, so what the demo shows and what the backend stored can't drift apart.

    Data contracts

    Written once in zod in packages/core/src/schema, mirroring the FastAPI models (architecture §4). The web app parses every response with them, and the fixtures are validated against them in tests.

    
  
    Token reference
    Components use semantic tokens only. Each direction is one CSS file setting these variables under [data-dir]; Tailwind exposes them as bg-surface, text-ink-2, rounded-ui and so on.
